# B0：ResNet50＋512 基线实验实现方案

## 一、实验定位与本次边界

本实验落实研究路线 5.1.4 中的 B0：**ResNet50＋512 方形输入画布＋单 logit＋普通 BCE**。其作用是建立训练充分、输入信息保留合理、验证可信的标准图像分类参照，用于后续比较 B1 的 768 输入、B2 的现代骨干，以及不平衡学习与鲁棒训练模块。

B0 不是当前 ResNet18 配置简单改两个字段后的试跑，也不是预先认定的最终提交模型。其研究价值在于把数据、图像处理、优化预算和评估口径固定下来，使改进能够归因。

本次仅分析本地研究路线与现有源码，编写实现方案；未修改源码或 YAML，未新建数据清单，未导入模型进行测速，未执行训练、测试集学习或提交。本文件中的参数、文件名和运行流程均为后续实施设计，不能当作已有结果或可直接运行的新增功能。

### 1.1 本实验回答的问题

1. 不使用外部知识、复杂采样或特殊损失时，常规中高分辨率 CNN 的排序能力是多少？
2. 该模型的错误主要集中在少数类、低质量、特定尺寸还是其他成像子组？
3. 512 输入的有效细节、显存和端到端延迟是否足以支撑后续研究？
4. 哪些训练限制是真正的建模瓶颈，哪些只是未收敛或接口实现问题？

不预设目标 AUROC 或涨分幅度；完成标准是协议执行正确、结果可复现且局限可解释，而非达到任意预定分数。

### 1.2 必须固定的实验身份

| 项目 | B0 约定 |
| --- | --- |
| 输入 | 仅 RGB 眼底图像；512×512 画布，保持有效视野宽高比 |
| 网络 | torchvision ResNet50，标准骨干、全局平均池化、2048→1 线性头 |
| 初始化 | 默认 `weights=None`，全网络从零训练 |
| 标签 | 主办方原始二分类标签，不重标注、不平滑 |
| 损失 | 普通 `BCEWithLogitsLoss`，`pos_weight=1`，按样本平均 |
| 采样 | 训练子集自然类别比例，每轮随机打乱，不按类别重采样 |
| 辅助信息 | 不使用年龄、文件名、尺寸标签或质量分数作为模型输入 |
| 其他模块 | 无 ROI 分支、AUC loss、MixStyle、AugMix、蒸馏、伪标签、TTA、集成或校准 |
| 选模 | 内部开发集 AUROC；官方验证集不参与逐轮早停 |
| 推理 | 冻结模型，单图一次前向，输出阳性概率 |

外部预训练获准后，可另设 `B0-pretrained` 初始化对照，但不能静默替换本实验；与随机初始化模型分别报告配方、成本和结果。

## 三、数据划分与信息边界

### 3.1 两个阶段，分别报告

**B0-dev：开发训练。** 从官方训练集固定划出内部开发集。只在其余拟合子集训练；内部开发集用于有限的配方选择和逐轮选模。官方 valid 不进入训练、预处理参数学习或逐轮早停；test 不进入任何训练操作。

**B0-fit：确认性重训。** 在开发协议冻结后，可使用完整官方训练集重新初始化训练，采用预先确定的训练长度与配方；在结束后评估官方 valid。它是同一方案在更大训练数据上的独立重训，不是直接加载 B0-dev 的 best 权重继续训练，也不是把官方 valid 合并进去。

由于选择过配方，官方 valid 最终比较也应控制次数；不能无限次查看成绩后仍称其完全独立。B0-dev 与 B0-fit 不混列为同样训练数据条件的结果。

### 3.2 内部开发划分

首选约 80% 拟合 / 20% 开发，固定划分种子 20261018；训练初始化种子首轮为 42。若患者或检查分组造成比例偏离，应优先保持组隔离并报告实际比例，不能为了精确 80/20 拆分患者。

患者/检查分组与已确认重复组是同时生效的隔离约束，不是互斥的优先级：同一可信患者/检查关联的样本、已确认重复/近重复的样本分别连边，取这些关联的并集连通分量作为最终 group。同一组的所有图像只能进入同一侧；疑似近重复未经确认不直接作为确定患者关联，更不自动合并所有视觉相似图像。

先按 `image_id.casefold()` 稳定排序；不允许排序键重复。存在多样本关联组时，首选 `StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=20261018)`，固定第 0 折为内部开发，其余为拟合；孤立图像各为独立组。完全没有可用关联约束时，使用 `train_test_split(test_size=0.2, random_state=20261018, shuffle=True, stratify=labels)`。记录 scikit-learn 版本与最终清单，不能按 AUROC 或更有利的标签比例择优选折。

若分组方案不满足可划分条件、某侧只有单类或实际规模明显不可用，应停止报告并另定协议，不能静默退回拆组随机划分。没有患者 ID 时明确声明“未能排除同一患者双眼跨划分”，不能以感知哈希代替患者识别。各集合逐一记录总数、阳性数、阳性率及跨组重叠检查。

官方 train 约 51,396 张、阳性约 3.2% 只作为研究路线中的暂定规模；按 20% 估算开发集约 1 万张、数百张阳性，并不是本次审计得到的精确统计。实际数值必须来自冻结后的清单。

### 3.3 与现有接口兼容的清单组织

建议将开发清单单独保存为 `data/manifests/glaucoma_b0_dev_v1/`：

- `train.csv`：仅内部拟合部分，训练角色 `split=train`。
- `valid.csv`：内部开发部分，训练角色 `split=valid`，不是官方 valid。
- `summary.json`：来源为官方 train、划分种子、组依据、每类计数和限制。

保持已有 `image_id,image_path,label,age,split` 字段，原始图像不移动、不复制；通过来源记录明确它们均来自官方 train。官方 train/valid/test 保存在独立官方清单版本中，不能把内部 valid 与官方 valid 混用。B0-dev 不需要把测试清单复制进开发目录，开发训练代码也不得读取它。

现有训练函数可读取一个目录下的 train/valid，因此角色映射可复用，但现有清单构建函数默认按官方划分生成，**仍需新增内部划分生成逻辑**。当前 ID 不重叠检查也不能代替内容重复或患者分组检查。

### 3.4 数据异常处理

无法读取、标签非法、ID 重复等错误在训练前解决；不得在 `__getitem__` 中悄悄跳过样本。疑似标签错误仅记录，不自动改标；低质量或难例不因模型预测不佳被删除。官方划分发现重复时保留原始资料并说明，另报敏感性分析，不悄悄改官方评估口径。

## 四、512 输入的具体处理流程

### 4.1 总体顺序

`解码并转 RGB → 保守 FOV 外围裁剪 → 训练时常规增强 → 等比缩放与居中填充至 512 → ToTensor → 固定归一化`。

验证与推理使用完全相同的确定性 FOV、缩放、填充和归一化，关闭所有随机增强。B0 不使用视盘检测器，不把 FOV 裁剪称为 ROI 定位。

### 4.2 保守 FOV 裁剪候选算法

目的只是减少外围黑边，不推断视盘位置。以下数值是首选实现候选，必须在内部拟合部分的代表图像上检查后冻结，不能冒充已经验证的最优阈值：

1. 图像按最长边不超过 512 缩成仅用于边界检测的预览；不改变原文件。
2. 对预览定义 `M=max(R,G,B)>8`，RGB 范围为 0—255。某行/列中至少 1% 像素为前景时，将该行/列视为有效边界候选；取有效行列的包围框。
3. 将预览包围框映射回原图，坐标向外取整，在框宽/高两侧各扩展 2% 安全边距，裁剪到原图范围内。
4. 若前景为空、框无效、裁剪面积小于原图 50%，或框内未保留至少 99.5% 的预览阈值前景，则回退整幅原图。检查指标在同一预览坐标系计算，避免尺度换算口径不一致。
5. 文本、水印、反光可能使框偏大；B0 宁可保留多余黑边，也不为追求紧致裁剪移除可能有效的眼底结构。

实现坐标统一为半开区间 `[left,top,right,bottom)`。预览边长按 4.4 节同样的 round-half-up 规则确定；有效行/列的右、下界取最后一个有效索引加 1。预览至原图用实际宽高比分别映射，左/上向下取整、右/下向上取整，安全边距向外取整。覆盖率使用最终原图框映回预览、向外取整并裁限后的框计算，分母为整个预览的 M 前景像素数；面积比使用原图坐标。前景为空时先回退，不做除零。

以上是图像规则，不新增分割监督。逐样本可记录裁剪框、面积比、回退原因；汇总报告回退率和裁剪比例。不把所有包围框图另存成一套全量图像，避免不必要的数据复制。

先查看正常曝光、极暗、强反光、宽黑边、偏心视盘和非方形视野案例。若规则无法可靠通过图像检查，则改用“原图等比填充”的明确变体并记录；此时不能继续将其描述为已经成功去黑边的 B0。阈值或规则变化后应重新冻结预处理版本，不在同一正式运行中途调整。

### 4.3 常规增强

| 操作     | 首选设置                        | 控制要求                                         |
| ------ | --------------------------- | -------------------------------------------- |
| 水平翻转   | 概率 0.5                      | 无眼别任务输入；训练使用，验证关闭                            |
| 小角度旋转  | 每张采样 `Uniform(-10,10)` 度    | 双线性插值、`expand=True`、RGB 黑色填充，再最终等比缩放，避免截断边缘  |
| 亮度/对比度 | 两个因子独立采样 `Uniform(0.9,1.1)` | 每张均应用；固定先亮度、后对比度，不另随机交换顺序；无色相/饱和度扰动          |
| 其他     | 不开启                         | 无垂直翻转、随机大裁剪、CutMix/MixUp、模糊链、CLAHE、锐化或质量增强网络 |

固定顺序为 FOV → 水平翻转 → 旋转 → 亮度 → 对比度 → 等比缩放/填充 → 张量/归一化。随机数受训练种子和 worker 种子控制；记录实际增强后端及版本，不把随机顺序 ColorJitter 默认为上述固定顺序。

这些操作仅为 B0 的固定常规增强；后续鲁棒性实验需在此基础上改变一个明确因素。旋转扩展会轻微改变内容占比，必须连同缩放规则写入配置；在原始高分辨率上增强也可能增加 CPU 训练耗时，应记录，不能为加速悄悄更换输入内容。

### 4.4 等比缩放、填充与归一化

对裁剪/增强后图像宽高 W、H，取 `r=min(512/W,512/H)`，明确使用 round-half-up：`w'=min(512,max(1,floor(W*r+0.5)))`，h' 同理，不混用 Python 的银行家舍入或直接截断。采用 Pillow RGB 图像的双线性 resize 后端，其缩小滤波行为随固定 Pillow 版本记录，不以“支持时”在不同路径任意切换抗锯齿策略。

居中放入 RGB=(0,0,0) 的 512×512 画布：`left=floor((512-w')/2)`、`top=floor((512-h')/2)`，剩余差额分配到右侧/下侧。训练、验证、预测复用同一函数与版本，禁止一条路径用 PIL、另一条改成不同张量插值而不验证差异。

ToTensor 将 RGB 转为 `[0,1]` 浮点张量；B0 随机初始化路线使用固定 `mean=[0.5,0.5,0.5]`、`std=[0.5,0.5,0.5]`，即映射为 `[-1,1]`。这是一项固定配方选择，不是估计的数据统计或最优性结论，不需要利用验证/测试图像。黑色填充归一化后为 −1。

如日后采用训练集统计归一化，单列配置变体，统计仅来自该轮拟合子集；如获准采用特定预训练权重，按其输入要求单独设计初始化对照，不与 B0 的变化混为一项。B1 优先沿用 B0 的处理，只将画布改为 768。

## 五、模型、损失与批次构成

### 5.1 模型结构

使用标准 `torchvision.models.resnet50(weights=None)`，不冻结任何骨干层；原分类头替换为全局平均池化后的 `Linear(2048,1)`。当前工程先将原 `fc` 设为 Identity，再套一层分类头，语义可复用；将其 Dropout 设为 0，避免增加非必要差异。

输入形状为 `[B,3,512,512]`，输出为 `[B,1]`；标签为 float32 的 `[B,1]`。训练把原始 logit 送入 BCEWithLogitsLoss，不先 sigmoid；推理才输出 `sigmoid(logit)`。保留 logit 与概率，AUROC 可同时核对两者排序，避免极端概率数值饱和造成并列却未被发现。

保持 ResNet 的正常 BatchNorm：训练用批次统计，评估调用 `eval()`，不在官方 valid/test 更新其统计。梯度累积不能模拟相同大物理批次的 BatchNorm，不因此声称与真实 batch=32 完全等价。

### 5.2 普通 BCE 的定义

设第 i 个样本 logit 为 z_i、标签为 y_i，`p_i=sigmoid(z_i)`，批次损失为：

`L = mean_i[-y_i log(p_i) - (1-y_i) log(1-p_i)]`。

数值实现使用 BCEWithLogitsLoss，而非直接对 p 取对数。固定 `pos_weight=1`、无类别权重、无标签平滑、无困难样本挖掘。训练负样本多并不构成擅自加入约 30 倍正类权重的理由；加权 BCE 是后续 L1，不属于 B0。

### 5.3 自然比例批次

采用随机打乱后无放回遍历，每轮覆盖拟合子集，不使用 WeightedRandomSampler，不要求每个批次都有阳性。零阳性批次的普通 BCE 是合法的，不因为它存在而跳过该批。

建议首选物理 batch=16、累积 2 次，名义有效 batch=32；这是待显存预检的资源设置，不是 T4 已验证结论。若物理 batch=8、累积 4 次才能运行，应在正式启动前固定并记录，B0/B1 尽可能保持相同物理批次；有效批次接近不等于 BatchNorm 相同。

训练原则上不丢最后一批，评估绝不丢。全局池化之前仍有空间维，物理尾批为 1 的情况需用目标网络预检，不凭空宣称一定失败或一定安全。不能遇到尾批错误后自动删样本而不记录。

## 六、首选训练配方及其冻结方式

### 6.1 拟定默认值

以下构成 B0 随机初始化路线的首选配方，需完成数值/资源预检后才冻结。不是已训练得到的最优参数，也不能沿用旧工程 20 轮、1e-4 后直接宣布充分收敛。

| 参数 | 首选值 | 说明 |
| --- | --- | --- |
| 优化器 | AdamW | 复用现有优化器类型 |
| 峰值学习率 | 1e-3 | 以有效 batch≈32 为起点，不自动按 GPU 数量缩放 |
| 权重衰减 | 1e-4 | 对所有可训练参数采用同一设置；不隐式另加参数组策略 |
| betas / eps | (0.9,0.999) / 1e-8 | 在配置中明确记录 |
| 最多轮数 | 80 | 是收敛预算，不保证必须跑满或足够 |
| warmup | 5 轮对应的预期更新组数 | 按成功更新索引由 1e-4 线性升至 1e-3；跳步时可能超过 5 个实际数据遍历轮次 |
| warmup 后 | 余下预算余弦衰减至 1e-6 | 调度总长度在启动前冻结 |
| 最短训练长度 | 30 轮 | 未达到前不因开发集短期波动自动早停 |
| 早停 patience | 15 个评估轮次 | 与下文显著改善阈值配套 |
| AMP | CUDA 上 float16 autocast＋GradScaler | 待实现与目标硬件预检；数值问题时显式切换 FP32 变体 |
| 梯度裁剪 | 全局范数上限 5 | 在 AMP unscale 之后、优化器更新之前 |
| 首轮种子 | 42 | 入围复验建议 43、44，不能只报告最好的一次 |
| 加载器 workers | 从 0 预检，目标候选 4 | 根据平台、内存与读取吞吐冻结；不必盲目开到 CPU 总数 |
| 模型选择 | 内部开发 AUROC，逐轮评估 | 0.5 阈值召回和准确率不作为检查点主选择条件 |

开发集每轮用 `eval()`、FP32 前向和损失评估，评估 batch 首选 16、`drop_last=False`；资源不够时在正式运行前独立冻结较小的 eval batch，不改变训练 batch 或选模精度。训练 AMP 与评估 FP32 是明确的两个设置，不能因开启训练 AMP 就默认改变检查点选择精度。

配方是否合理应结合梯度、损失与训练/开发曲线判断。若出现学习率明显不适配的证据，可在正式 B0 前进行一次预先限定的小规模配方试验，例如比较 3e-4 与 1e-3；使用相同训练子集、相同步数，记录额外成本，不能无限调参或借少量步骤的 AUROC 宣称最终性能排名。

### 6.2 累积与 AMP 的具体更新逻辑

以物理 batch=16、累积 2 次为例：

1. 一个累积组开始时清空梯度；依据冻结清单、物理 batch 和余数得到该组实际样本数 n_g，每个微批次的 BCE 损失和除以同一个 n_g 后反向。不得取微批次均值再不加区分地平均。
2. 前向在 autocast 中进行；关闭 autocast 后对 `logits.float()` 和 float32 标签使用 BCEWithLogitsLoss。输入、logit 或未缩放损失非有限时立即失败；这不同于有限损失反向后出现的 AMP 缩放梯度溢出。
3. 用同一 GradScaler 缩放该组所有微批次的损失并反向；最后不足两个微批次时照样按实际 n_g 归一化，不一律除以 2。
4. 组结束时仅调用一次 `scaler.unscale_(optimizer)`。梯度元素均有限时计算全局范数并裁剪至 5；范数本身非有限则报告失败。若 unscale 后存在非有限梯度，不进行裁剪，不先用 `error_if_nonfinite=True` 抛错截断 scaler 的正常溢出处理；继续由 `scaler.step/update` 跳过更新并降低 scale。
5. B0 只使用一个优化器、标准 GradScaler，固定 `init_scale=65536,growth_factor=2,backoff_factor=0.5,growth_interval=2000`，不手动指定 `update(new_scale=...)`。记录 update 前后的 scale；在该约束下，`scale_after < scale_before` 判为溢出跳步，其他情况判为成功。**不得用 `scaler.step()` 或 AdamW `step()` 的返回值是否为 None 判断成功。** 后续若改变 scaler/多优化器机制，需同步改判定协议。
6. 只有成功更新才增加 successful_updates；跳步增加 skipped_groups，不推进成功更新索引。每组结束清空梯度，跳步组不重新喂入数据，不伪称它贡献了优化更新；训练损失仍记录这些已消费样本，另报成功组样本数。
7. 首选连续 8 个累积组跳步即中止，作为可配置、启动前冻结的数值安全阈值；单次成功更新后连续计数归零。FP32 模式下任何非有限梯度立即失败，不走 scaler 退避。禁止自动关闭 AMP 或降低学习率后继续记作同一运行。

训练损失日志使用未缩放、按真实消费样本数平均的损失；不把累积除数、scaler 数值或组均值当作 train BCE。梯度范数、scale 和跳步计数用于判断异常，不通过清零 NaN、忽略失败或隐藏丢批维持表面完成状态。

#### 6.2.1 学习率调度的精确定义

设拟合样本数为 N、物理 batch 为 b、累积次数为 a，均取冻结配置且 `drop_last=False`：

- 每轮微批次数 `M=ceil(N/b)`，每轮预期更新组数 `G=ceil(M/a)`；累积组不跨 epoch。
- 完整调度长度 `U=80*G`，warmup 长度 `Uw=5*G`。开发早停只截断运行，不重新压缩余弦周期。
- `s` 为此前成功更新总数，初始 0；本组尝试的更新编号 `j=s+1`。在本组优化器 step **之前**设置本组学习率；失败跳步后 s 不变，下一组仍使用同一 j 的学习率。

冻结函数为：

```text
1 <= j <= Uw:
    lr(j) = 1e-4 + (1e-3 - 1e-4) * (j - 1) / (Uw - 1)
Uw < j <= U:
    q = (j - Uw) / (U - Uw)
    lr(j) = 1e-6 + 0.5 * (1e-3 - 1e-6) * (1 + cos(pi * q))
```

N>0 且本配方 Uw≥5，分母不为零。首次成功更新使用 1e-4，第 Uw 次成功更新使用 1e-3，第 U 次使用 1e-6。不得再叠加一个每微批次推进的 scheduler。若用库 scheduler 实现，必须通过这些边界测试，并避免构造器或调用顺序提前消费首步。

轮数到预算上限即结束，不为补齐 AMP 跳步延长数据遍历；因此存在跳步时可能尚未达到第 U 次成功更新，最后实际学习率也可能高于 1e-6，必须如实记录。每轮报告首/末实际更新学习率、attempted_groups、successful_updates、skipped_groups，不用预计值代替实际更新数。

### 6.3 早停与 best 检查点

每轮训练完成后完整评估内部开发集。best 检查点按未四舍五入的 AUROC 严格更高时更新；完全相等时保留更早的轮次，不临时按召回或阈值改选。

patience 使用独立的“有实质改善”参考值，固定 `min_delta=1e-4`。以下为唯一状态更新顺序，epoch 从 1 开始；参考值只在累计改善超过 min_delta 时更新，而不是每次 tiny best 都更新：

```text
初始化 best_auc=-inf, best_epoch=None, reference_auc=None, stale=0
每轮完整开发评估后，先验证 auc 有限且两类齐全，否则失败：
    if auc > best_auc:
        best_auc=auc; best_epoch=epoch; 保存本轮最佳检查点
    # 完全相等不替换较早 best
    if reference_auc is None or auc > reference_auc + 1e-4:
        reference_auc=auc; stale=0
    else:
        stale += 1
    if epoch >= 30 and stale >= 15:
        本轮记录与检查点落盘后早停
```

stale 从第 1 次评估后就开始按上述规则累计，不在第 30 轮重置；第 30 轮前只是不执行早停。warmup 期间成绩也可成为 best，`min_epochs=30` 限制的是开发运行何时允许停止，不是禁止保存较早 best。保存 best、last 和这两套状态，报告最佳轮次与总实际轮数。

若到 80 轮训练与开发仍持续改善，则说明预算可能不足，应记录“未确认收敛”，再单列延长预算的修订实验；不能事后把 80 轮设定说成已证明足够。多种子复验采用冻结配方，不逐种子重新调参。

### 7.1 先确定产物位置

本方案文档位于 `03_Method_and_Experiment`；未来训练产物仍在工程 `experiments` 下。首轮拟用：

- 开发配置：`configs/b0_resnet50_512_dev_v1.yaml`。
- 有界预检输出：`experiments/b0_resnet50_512_preflight_s42_v1/`。
- 开发输出：`experiments/b0_resnet50_512_dev_s42_v1/`。
- 后续全训练集重训：`experiments/b0_resnet50_512_fit_s42_v1/`。

以上均尚未创建。每次实施先确认目标未占用，同名存在就停止并选择明确的新版本，不能覆盖、删除或运行中途改目录。其他种子使用独立目录，不混入 s42 产物。

### 7.2 轻量预检顺序

1. 核对独立 Python 环境、项目导入、CUDA 可用性和指定 GPU；正式运行明确指定 CUDA，避免 `auto` 静默退回 CPU后仍当作相同训练预算。
2. 读取配置与冻结清单，核对标签、图像路径、开发来源、无重叠和默认权重关闭；不能先下载预训练再发现规则不允许。
3. 在内部拟合子集选择少量代表图像，检查 FOV、512 输出形状和增强结果；属于 1.3 节授权实现任务中的有界预检，不据此另启全量图像导出或质量标注。
4. 用目标 ResNet50-512 跑一个含两类样本的调试批次，检查输出、BCE、梯度有限以及参数确实更新；这种刻意构造的调试批次不改变正式自然采样策略。
5. 用同一物理 batch 验证 AMP、两个微批次累积及尾组；和 FP32/样本数加权参照作合理误差检查，不要求不同精度逐位相等。
6. 保存加载一次检查点，确认加载不触发外部下载，预处理元数据完整，`eval()` 预测重复一致且 BatchNorm 不更新。
7. 在 1.3 节预算内测训练峰值显存、短程吞吐和少量单图推理路径；不把预检当成 9.2 节完整计时认证。完成后输出是否具备启动条件，若当次没有完整训练授权则停止。

如需短程训练，仅检查数值、调度和记录链路，先限定样本数/更新数，明确不是 B0 最终结果。不能根据小样本调试 AUROC 或几步损失决定算法胜负。

### 7.3 正式运行与中断

正式阶段按冻结的 B0-dev 配方训练，每轮输出样本数、更新数、学习率、损失、开发 AUROC/AP和耗时。长任务分别报告开始、预检完成、完整训练开始和完成。

发生错误立即报告：完整训练是否已开始，完成的 epoch/更新/样本数，失败位置，已有配置、日志和检查点路径。不要自动改变 batch、损失、划分或精度后续跑成“同一个 B0”。

当前工程没有完整断点恢复功能。若不实现恢复，则失败后新版本从头重跑并保留部分产物；若实现恢复，至少保存 model、optimizer、scheduler、scaler、epoch/global_step、早停状态以及 Python/NumPy/Torch/CUDA 和加载器随机状态。初版可只支持轮次边界恢复；不能承诺任意微批次中断后无缝复现。

## 八、评价、错误分析与 B0-fit 重训

### 8.1 B0-dev 必须输出什么

- 每轮训练仅要求按真实消费样本平均的 train BCE、消费/成功组样本数、学习率、更新计数、耗时和 AMP 跳步数；**不默认额外完整评估训练集，不要求每轮 train AUROC/AP**。
- 每轮内部开发要求一次完整、确定性 FP32 评估，输出 dev BCE、概率 AUROC/AP及 0.5 阈值混淆指标；AUROC 检查点选择明确使用 float32 logit 经 FP32 sigmoid 得到的概率。原始 logit 排序指标可作为饱和检查另报，不能中途切换选模依据。
- 最佳模型完整开发集预测：`image_id,label,logit,probability`，顺序与来源清单可追溯，无缺失和重复。
- 0.5 阈值下的混淆计数、灵敏度、特异度、精确率和 F1；Brier 分数和基本概率分布。
- 样本总数、阳性数、阳性率以及恒定先验预测参照。预测全部小于 0.5 可能与低阳性率有关，不能据此自动认定 AUROC 为零或模型完全未学习。
- 主要尺寸、清晰度/曝光代理等子组结果，子组规则只在拟合部分确定；单类组 AUROC 记为不可计算，不填 0。
- 假阴性/假阳性案例索引与必要的输入/注意力检查；不擅自改标签、删样本或公开比赛图像。

现有指标输出的是 `average_precision`。官方 AUPRC 若采用其他积分定义，应另行计算并说明；本实验不把 AP 无条件重命名成官方 AUPRC。保留未四舍五入概率和必要精度的 logit，保证后续配对比较可用。

### 8.2 不确定性

关键 B0 结果建议用种子 42/43/44 复验，固定划分，不挑最好一次替代均值与标准差。配对方法比较共享同一评估图像；有患者 ID 时按患者 bootstrap，无 ID 时图像级结果注明相关性未校正。B0 开发选模结果不是外部临床验证结果。

### 8.3 B0-fit 的训练长度与官方验证

本阶段不在首次交接的默认执行范围。获准开展时，选取冻结配方、同一内部划分下已完成的种子集合；不能删除不利种子或混入不同配方的试跑。记其最佳轮次为 E_best，正式重训前固定：

`E_raw=ceil(median(E_best))`，`E_fit=min(80,max(30,E_raw))`。

只有一次开发训练时令 E_raw 为该次 best_epoch，并明确不确定性。若有未完成/数值失败的预定复验，先报告而非自动当作不存在。若 E_raw<30，记录因重训最短预算提升到 30 轮；这意味着 B0-fit 终点不对应较早的开发 best，不能声称精确复现其训练轨迹。若较早 best、过拟合或未收敛使该规则明显不适配，应先报告并另定版本，不根据官方 valid 分数回调 E_fit。

全官方训练集重新初始化，固定训练 E_fit 轮，关闭开发早停及按官方 valid 保存 best 的逻辑；只保留固定终点模型用于该次官方评估。开发的最短 30 轮原本只限制允许早停的时机，本节另行显式规定全量重训最少 30 轮，消除二者含义混淆。

重训按完整官方 train 的样本数重新计算 G_fit，采用 `U=80*G_fit`、`Uw=5*G_fit` 及 6.2.1 节同一学习率函数，实际只遍历 E_fit 轮。不能用配置 `epochs=E_fit` 顺带把余弦总周期改成 E_fit；应将运行轮数与 `schedule_total_epochs=80` 显式分开。若 E_fit<80，学习率尚未衰减至最小值是预先约定的截断，而不是 scheduler 错误。

此时使用固定终点模型评估官方 valid，单独报告为 B0-fit，而非声称在官方 valid 上选得的“best”。不把该终点成绩回灌开发早停，不按官方 valid 逐轮挑选模型。

如果开发已显示欠拟合或训练不稳定，应先解决配方问题，不能为了尽早查看官方分数跳过开发冻结。查看官方结果后的任何实质修改，都需要记录其探索性质与额外比较次数。

## 九、资源与交付判断

### 9.1 训练成本

以目标物理 batch、512 输入测峰值显存和稳定吞吐，记录 CPU 解码、FOV 和增强开销。只用短程吞吐粗估每轮/总时长，并说明冷缓存、Windows 多进程等影响；此次没有测速，不能给出可靠小时数或 T4 可行性结论。

训练验证频率、早停预算和梯度累积都影响成本，必须与后续 B1/B2 的训练预算一起记录。AMP 是资源手段，不是默认涨分模块；未实现时不能靠 YAML 声明完成。

### 9.2 单图端到端测速

冻结模型，以 batch size=1 计时 `读盘/解码→FOV→缩放填充/归一化→CPU-GPU 传输→前向→sigmoid/结果转换`。模型加载和预热单列，GPU 在计时边界同步；同时报告模型前向耗时和完整路径耗时，不能互相替代。

内部候选口径为先预热 20 次，再在覆盖尺寸与压缩差异的至少 100 张代表图像上记录均值、P95和最大值；这是拟定内部评估，不是官方计时标准。磁盘缓存状态和软硬件版本需要记录。最终以举办方标准为准，不能因均值小于 100 ms 就推断必然通过最大值限制。

可先用 FP32 推理作为明确参照；FP16 推理若采用，单独报告输出差异、指标与延迟并确认规则。权重大小统计推理所需权重和参数，不包含优化器状态，不把含优化器的训练检查点大小直接当成部署大小，也不通过压缩绕开“压缩前”限制。

### 13.4 数据分片、随机性与尾批

所有进程读取同一份冻结内部拟合/开发清单，不各自重新划分。训练使用共同种子的分布式随机采样器，每轮在创建迭代器前调用 `set_epoch(epoch)`；设置 sampler 后不同时启用 DataLoader 的 `shuffle=True`。模型初始化保持相同基础种子，初始化完成后按 rank 派生数据增强和加载器随机流；各 rank 的 sampler 种子必须一致，不能用不同 sampler 种子破坏分片互斥性。

第一版限定拟合样本数 N 能被 W=4 整除。普通 `DistributedSampler(drop_last=False)` 在不能整除时会填充重复索引，`drop_last=True` 则会丢样本，均不能静默视为原有“每轮自然遍历一次”。不满足整除条件时停止并报告，后续另定等步数、无重复的尾部协议；不临时重复、删除样本或拆分关联组。DataLoader 仍设 `drop_last=False`，保留微批次尾部。

训练器必须按本 rank 采样器的实际长度或实际累积组样本数工作，不能继续用全局 `len(loader.dataset)` 计算 `group_samples` 或要求本进程消费整个数据集。对每轮核对本地消费数，并汇总全局消费数；无跳过数据且完成一轮时应恰为 N，AMP 跳步不改变“已消费”的样本数。

仅作算例：若冻结清单确为 N=41,116，则每卡 n=10,279。取 b=16、a=2，每卡 643 个微批次、每轮 322 个全局更新组；最后一组每卡 7 张，合计 28 张。实际值必须从当前清单重新计算，不能将此算例写死。开发集 10,280 张同样只是已有划分参照。

`num_workers` 按每进程解释：4 表示四卡合计 16 个，8 表示合计 32 个。第一版从每卡 4 开始，后续独立比较每卡 8；在 PPU/CUDA 通信环境下采用经验证的 `spawn` 或 `forkserver` 加载进程上下文，避免初始化设备/通信后再不安全地 fork。保留可追溯的 worker 随机种子，不自动启用新的持久 worker 随机协议。

### 13.5 损失归一化、梯度累积与 AMP 一致性

每个累积组先确定本 rank 的实际样本总数 n_g；对微批次均值损失按 `microbatch_samples/n_g` 缩放后反向。第一版各 rank 的 n_g 相同，DDP 对梯度取平均后即得到全局组的样本均值梯度，**不得再额外除以 W**。若未来允许各 rank 组样本数不同，须重新推导加权规则，不能直接沿用本章公式。

非最后一个微批次使用 DDP `no_sync()`，且上下文同时包住前向与反向；最后一个微批次正常同步，包括只有一个微批次的尾组。BCE 继续按 6.2 节在 FP32 中计算，训练损失日志记录未缩放 BCE 的样本加权均值，不记录用于 backward 的累积缩放值。

保留既有单优化器、GradScaler 参数、梯度裁剪与连续跳步阈值。四个进程必须从相同 scaler 状态出发，在组末完成梯度同步后各执行一次 unscale，并检查梯度有限性；在任何优化器 step 之前通过一致性检查确定本组成功/溢出决策。正常路径应使所有 rank 一致成功或一致跳步。若有限性或 scaler 状态不一致，立即整组失败，不能让部分进程先更新后再发现分歧，也不能仅广播布尔值却任由 scaler 内部状态不同。

实现时须明确验证标准 GradScaler 的溢出检测和更新在四 rank 上一致，不依赖优化器返回值，不通过修改私有 scaler 状态、清零非有限梯度或手工调 scale 掩盖不同步。梯度元素有限但裁剪范数非有限时沿用失败规则；输入、logit 或未缩放损失非有限仍属于致命错误，不归为普通 AMP 跳步。FP32 非有限梯度直接失败。错误退出见 13.9 节。

### 13.6 全局更新计数、调度与 BatchNorm

当 N 可被 W 整除时，定义 `n=N/W`、`M_rank=ceil(n/b)`、`G=ceil(M_rank/a)`。G 是一轮全局更新组数，不是四个进程计数之和；继续使用 `U=80*G`、`Uw=5*G` 和 6.2.1 节学习率函数。attempted/successful/skipped 每个全局组只计一次，只有所有 rank 成功更新后 successful_updates 才增加；跳步后各进程复用同一成功更新索引及学习率。

所有进程保持相同优化器、调度、scaler 和早停状态。全局已消费样本数、成功组样本数可汇总各 rank 的本地样本数；更新数不得求和变成四倍。不能把每卡步数与全局样本数混入同一列。

第一版保留普通 BatchNorm。每卡 b=16 的统计范围不同于旧单卡 b=64，梯度累积不会将 BatchNorm 统计合并为全局 batch 128；DDP 默认缓冲区广播也不等于 SyncBatchNorm。因而该运行应标明为四卡普通 BatchNorm 变体，不以与单卡参数逐位相同作为验收条件。

验证前显式将 rank 0 的模型缓冲区（含 BatchNorm running mean/variance 和计数）同步至其他 rank，确保各卡评估同一个模型状态；保存权重采用该统一状态。SyncBatchNorm 如后续需要，应单列兼容性、通信成本及效果验证，不在第一次四卡改造中默认加入。

### 13.7 全局开发指标、早停与验证通信

开发集使用确定性、无补齐的分片，例如按清单索引 `rank::W` 分配；每张图像恰好预测一次，允许各 rank 分片长度不同。统一参数/缓冲区后，以 `eval()`、无梯度、FP32 调用解包模型进行预测，避免不等长验证循环反复触发 DDP forward 的集合通信。验证结束后再由所有 rank 按同一顺序参与结果汇总。

rank 0 汇总 `image_id,label,logit,probability`，按原 manifest 顺序恢复并检查总数、唯一性和标签匹配，在完整开发集上计算概率 AUROC、AP、Brier 与阈值指标。**不能平均各 rank 的 AUROC 或 AP**；AP 与官方 AUPRC 的区别继续按 8.1 节记录。开发 BCE 通过损失总和/实际样本总数汇总，不平均不同长度分片的均值。若通信需要张量补齐，必须用真实长度剔除占位结果，不能把它们计入指标。

rank 0 按 6.3 节维护 best、reference_auc、stale 和早停决策；将状态与继续/停止决定广播至所有 rank。指标检查、保存或汇总失败时整组退出，不能让其他 rank 进入下一轮后等待。验证传输方案应适配已验证的 PPU 后端，不假定 CPU 张量或任意 Python 对象都能直接通过该后端传输。

### 13.8 单写入、检查点与推理兼容

只有 rank 0 创建公共实验目录、写配置快照及公共 CSV/JSON、保存检查点和生成最佳开发集分析；其他 rank 不执行同名文件写入。目录创建及已有目录冲突结果须通知全部进程，不能让 rank 0 失败而其余进程永久等待。

拟用正式目录 `experiments/b0_resnet50_512_dev_ddp4_ppu_s42_v1/`，预检拟用 `experiments/b0_resnet50_512_preflight_ddp4_ppu_s42_v1/`。均在执行前确认未占用；若已存在，先选定新版本，不覆盖或在运行中换目录。保留既有最佳检查点、正常完成时最终别名及失败状态记录语义，不把任意 `epoch_XXXX.pt` 声称为每轮必存的权重。

保存解包模型 `model.module.state_dict()`，避免出现 `module.` 键前缀；检查点记录新协议、W、每卡/global batch、后端、普通 BatchNorm、设备映射和实际环境。兼容修改必须覆盖配置校验、CLI 路由、B0 专用推理清单要求及检查点加载，使 DDP 权重能够在**不初始化分布式进程组**的普通单卡评估/预测中加载，继续使用同一预处理与提交文件流程。

数据划分协议与运行协议须区分：当前开发清单摘要使用 `b0_dev_v1` 标识其生成规则，四卡运行不因此要求重建相同划分或将摘要改名。可复用原划分校验并新增运行协议映射，不削弱来源、路径和隔离检查。当前没有完整断点恢复，本章不新增恢复承诺；若未来实施恢复，还需保存各 rank 随机状态并限定卡数及恢复边界。

### 13.9 日志、计时和失败处置

复用既有 `updates.csv`、每轮报告和运行清单，明确每列为本地还是全局值。由 rank 0 按冻结间隔输出当前 epoch、全局消费样本/总数、成功更新/跳步数、学习率和累计耗时，使终端无需等完整 epoch 才看到进度；不让四个进程重复刷相同日志。记录各 rank 峰值显存以及最大值。

训练计时包含取数、传输、前后向和同步，在相同计时边界同步设备；训练吞吐以全局实际消费样本数除以最慢 rank 的训练阶段耗时计算，不把四张卡耗时相加作为分母。验证、结果汇总、保存及报告耗时单列，并记录覆盖这些步骤的完整 epoch 墙钟时间；训练样本吞吐与完整轮次耗时不能互相替代。同步 AMP 跳步的样本只计为消费，不能计为成功优化样本。

进程组使用有限超时，异常应传播给启动器并终止同组进程；不要在某个 rank 已失败时无条件执行最终 barrier。错误报告包含是否进入正式训练、已完成轮次/全局更新/消费样本、失败 rank 与阶段、已有部分产物。不能自动降卡、降精度、改 batch 或重启同一输出目录来隐藏失败。失败清理只涉及本任务进程组，不触碰 DeepSeek 服务。

### 13.10 分阶段预检与速度验证边界

按以下顺序实施；上一阶段通过只证明相应能力，不替代下一阶段验收：

1. **本地小型验证。** 使用小模型/合成数据检查四进程数据分片、尾组损失权重、全局更新、指标汇总、早停广播、单写入及权重加载。可使用 CPU/Gloo 验证控制逻辑，但不据此认定 PPU 后端或 AMP 可用。数值参照用不含 BatchNorm 的小模型，避免把统计差异误判为累积错误。
2. **服务器通信检查。** 在现有容器和设备限制下完成四 rank 集合通信与退出检查，不消费真实训练图像，不替换环境。
3. **原预算内的真实图像预检。** 1.3 节的 64 个样本实例、最多 4 次尝试，均按全体 rank 的累计消费/全局更新组解释，不能每卡各给一份。四卡 b=4、a=2 时，一个 AMP 组消费 32 个实例，同等 FP32 参照再消费 32 个，合计 64；可验证小配置链路，不能证明目标 b=16 的显存、算子形状和吞吐已通过。
4. **目标配置扩展预检。** 四卡 b=16、a=2 的一个完整 AMP 组需 128 个实例；同形状 FP32 参照另需 128 个，合计至少 256 个，已超出原上限。执行前须单独明确并获准该扩展预算、总尝试数、图像范围和独立输出目录；本章列出预算不等于自动授权。需验证 AMP 数值、四卡更新一致性、保存/单卡加载及实际显存余量。
5. **短时速度比较。** 在单独明确的有限样本/更新数预算内，先预热，再比较同一 PPU 服务器单卡和四卡；固定数据、预处理、精度及全局 batch，记录 BatchNorm 微批次差异、冷/热缓存、总加载 worker 和共享服务负载。比较训练吞吐及完整轮次各阶段成本；若只处理固定子集，就报告子集墙钟时间，不外推为已测得的完整 epoch。此阶段不启动完整训练，也不使用少量样本 AUROC 调参。
6. **正式训练。** 仅在前述必要检查通过且用户要求正式运行后，冻结配置及新输出目录再启动。保留 80 轮调度、既有早停及完整开发评估，不以减少验证或更改预算伪装四卡加速。

AMP/FP32 数值参照必须从相同参数、优化器及 BatchNorm 起始状态出发，复用相同增强后的输入张量和微批次划分；不能先做 AMP 更新，再用已更新的模型或重新随机增强的数据充当 FP32 参照。FP32 参照若包含反向同样计入上述实例预算，比较采用预先约定的合理数值容差，不要求逐位相等。小配置预检与目标配置扩展预检如分阶段分别执行，各自使用启动前冻结的独立版本目录；不得复用已占用目录覆盖先前结果。

四卡只是吞吐提升候选，不预先承诺四倍加速。若共享资源、在线解码/FOV/增强或通信成为瓶颈，先用分阶段耗时定位，再决定是否调整每卡 batch、worker 或另建等价缓存；不在本章默认预生成固定 512 图像。

### 13.13 四卡精度与固定工作量预检修订（2026-10-20）

真实服务器的原FP16预检出现首组溢出、scale由65536退避到32768、第二组成功，但256实例/2组预算已耗尽，未执行FP32梯度对照。该报告证明过一次四卡更新和权重加载，不证明精度对照已通过、长期训练稳定或四卡提速。本修订按用户授权改变四卡精度路线，更新本章原FP16预检顺序；单卡旧协议不在本次修订范围内。

1. 显式支持 `training.precision: fp32 / fp16 / bf16`。FP32要求 `amp=false`；FP16/BF16要求 `amp=true`，但只有FP16启用GradScaler。旧四卡配置缺少precision时继续按amp解释，不改变旧检查点含义；验证和测试推理仍使用FP32。
2. 使用独立 `*_fp32_v2.yaml` 与 `*_bf16_v2.yaml` 配置和产物目录。两者均保持每卡16×累积2、全局128、workers4、同一划分及其余训练配方；记录精度变体，不能把不同精度结果当作完全相同的运行。FP32/BF16均不依赖FP16梯度缩放，仍保留输入、logit、BCE和梯度的有限性检查。
3. FP32预检固定为一次全局FP32更新（128实例/1组），检查四卡参数确实更新且一致、保存和单进程确定性加载；无需与自身重复执行混合精度对照，`precision_comparison=not_applicable` 不阻止其余检查通过后的 `status=completed`。
4. 混合精度预检固定为先FP32梯度参考、再一次目标精度更新（256实例/2组）。两条路径使用同一缓存增强张量、初始权重、BN状态和物理微批次，FP32参考不执行优化器step。沿用原损失和裁剪梯度容差；任何参考计算均计入总预算。提前拒绝不足以完成固定工作量的预算，即使上限更大也不追加尝试。FP16溢出时停止并保留已完成的FP32参考，不再出现“重试先耗尽参考额度”的顺序问题。
5. BF16在现有PPU栈执行小型卷积/反向算子检查，并通过目标ResNet50及FP32梯度参考确认可用。BF16不支持或精度超差时，不静默回退；若独立FP32预检通过，可明确选择FP32正式配置。若FP32也异常，保留失败阶段并先排查，不增加预算或关闭检查强行通过。
6. 预检输出阶段started/done与耗时，报告保存precision、stage_seconds、参考/目标路径峰值显存、更新及权重加载结论。小批确定性权重回测仅采用workers0以避免重复启动池，目标训练加载仍遵守配置；短程缓存吞吐不作正式训练速度依据。

完整服务器命令见 [README精度路线](../../Eye_Qing_Guang_code/README.md#ppu-precision-v2)。本次实现与本地合成回归均不授权或代表服务器正式训练已执行；服务器先FP32、后BF16预检的实际报告仍需保留。更改batch/累积或workers的吞吐比较安排在精度路线确认后。
