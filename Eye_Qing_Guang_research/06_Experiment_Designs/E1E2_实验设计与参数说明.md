> 整理时间：2026-10-26 17:38:44（北京时间，Asia/Shanghai）。本文件说明实际采用的实验思路、控制变量、完整参数及评估流程，不是训练进度或结果总结。参数以当前两份 FP32 YAML 为准，已核对 E1 运行目录保存的配置。

> GitHub 发布范围：本次只提交本实验设计文档。文中代码、YAML 配置、预检报告和训练产物的路径均指服务器独立实验目录 `e1e2_ppu_ready_v1/`；这些文件不随本次文档上传。模型权重待实验完成后另行整理。

## 1. 实验目的与对照关系

在同一套 ConvNeXt-Tiny、ImageNet-1K 初始化、512 输入、PW5 损失和 AdamW 训练方案下，考察两件事：

1. **池化方式**：平均池化（avg）与最大池化（max）对验证性能的影响。
2. **权重平均**：每条训练轨迹的原始权重（raw）与指数滑动平均权重（EMA）的表现差异。

E1 和 E2 是两次独立训练；每次训练同时维护 raw 与 EMA。因此是 **2 次训练、4 个评估分支**，不是 4 次独立训练。

| 实验 | 池化方式 | 原始权重分支 | EMA 分支 | 训练精度 |
|---|---|---|---|---|
| E1 | Global Average Pooling（avg） | E1-raw | E1-EMA，decay=0.99 | FP32 |
| E2 | Global Max Pooling（max） | E2-raw | E2-EMA，decay=0.99 | FP32 |

**已逐字段核对：两份配置除 `experiment.name` 和 `model.global_pool` 外完全一致。** EMA 是两组共同设置，不是 E1/E2 之间的不同变量。

### 设计假设（需要实验验证）

- avg 对每个通道的空间特征取平均，保留整体响应；max 取空间位置上的最大响应，突出最强局部响应。
- 待验证的问题是：当前任务更受益于整体特征汇总，还是局部强响应；max 的强响应也可能来自噪声，不能预先认定更好。
- EMA 对同一训练轨迹的参数做平滑，考察其验证性能是否比 raw 更稳定或更高。EMA 权重不反馈到 raw 优化路径，不额外执行一套反向训练。

建议按以下配对报告结果：E2-raw 对 E1-raw、E2-EMA 对 E1-EMA（池化差异）；E1-EMA 对 E1-raw、E2-EMA 对 E2-raw（EMA 差异）。四个分支都按相同验证规则选模，最佳轮次可以不同。

### 实际更新步数

当前训练集 51,396 张，每轮 67 个 optimizer 更新组：66 个完整组各 768 张，最后一个组 708 张。尾组按真实样本数归一化，不补样本、不按 768 错算。

若完成 100 轮：总计 6700 次 optimizer 更新；前 335 次更新为线性 warmup，之后 cosine 衰减。学习率按成功 optimizer 更新推进，不按每个 microbatch 推进。梯度累积采用实际样本数加权，并在参数更新前进行梯度裁剪。

## 6. EMA 的具体规则

| 项目 | 设置 |
|---|---|
| enabled | true，两组都启用 |
| decay | 0.99 |
| EMA 存储精度 | float32 |
| 初始化时点 | 第一次成功 optimizer 更新后复制当前 raw 权重 |
| 更新频率 | 每次成功 optimizer 更新后更新一次；不是每个 microbatch 一次 |
| 浮点参数/状态 | 第一次复制；之后按 0.99/0.01 加权 |
| 整数 buffer | 直接复制，不进行浮点平均 |
| 更新失败 | 不推进成功更新计数或 EMA 计数 |
| 一致性检查 | EMA 更新次数必须等于成功 optimizer 更新次数 |

首个成功更新后：`EMA = 当前 raw`。第二次及之后：

```text
EMA_new = 0.99 × EMA_old + 0.01 × raw_after_optimizer_step
```

因此完整的 16 个 microbatch 累积组只触发 1 次 EMA 更新。raw 负责梯度更新，EMA 分支用于验证和选模，不进行反向传播。

## 7. 验证、选模与早停

| 项目 | 规则 |
|---|---|
| 验证集规模 | 5,849 张，保持完整样本数 |
| 每轮验证 | raw 与 EMA 分别跑原图视图 |
| 验证精度 | FP32 |
| 主要选模指标 | ROC-AUC |
| best 权重保存 | 各分支 ROC-AUC 严格高于此前最佳时保存；分别保存 best_raw / best_ema |
| 辅助指标 | AP、PR-AUC、加权 BCE、Brier、Accuracy、Balanced accuracy、Precision、Sensitivity、Specificity、F1、混淆矩阵等 |
| 二分类统计默认阈值 | 0.5；不影响使用连续概率计算 ROC-AUC |
| early_stopping_enabled | true |
| min_epochs | 30 |
| patience | 15 |
| min_delta | 0.0001，绝对 AUROC 差 |
| 整体早停 | raw 与 EMA 的早停条件同时成立时才结束实验 |
| 重复预测一致性阈值 | `duplicate_logit_atol=1e-6` |

**保存 best 与早停计数的标准不同**：任何严格高于历史最佳的 AUROC 都可刷新 best；早停计数只有在超过该分支“显著提升参考值 + 0.0001”时才重置。未达到 min_delta 的微小进步不一定重置 patience。

### 训练结束后的固定对照

1. 分别重载 `best_raw.pt` 和 `best_ema.pt`。
2. 在原图验证集核验重载结果与保存时结果一致。
3. 分别进行固定水平翻转 TTA：对原图与水平翻转图的 **sigmoid 概率取算术平均**，不是先平均 logits。
4. 输出原图与 hflip 对照结果，不使用 hflip 结果反过来改变本次原图 AUROC 选模过程。

没有自动 test 推理、自动生成提交或上传比赛结果。

## 8. 运行环境与 FP32 选择

- 服务器：`172.22.3.104`；容器：现有 `qinghao_ppu_train`。
- 设备：物理 PPU7，`CUDA_VISIBLE_DEVICES=7`，进程内为 `cuda:0`；型号 ZW-M890P。
- 保留厂商 torch 2.11.0；timm 固定 1.0.22，不另建或切换 Conda 环境。
- 单进程单卡；distributed.enabled=false，world_size=1，gradient_transport=none，backend=none。
- DataLoader workers=6，multiprocessing_context=spawn；配置 cpus_per_rank=6。
- 启动脚本设置 OMP_NUM_THREADS=4、MKL_NUM_THREADS=4、OPENBLAS_NUM_THREADS=1。
- 每 10 个更新组及每轮末尾输出训练进度；每轮完成 raw/EMA 验证后写入报告。
- E1/E2 共用物理卡 7，手动启动器用锁保证串行运行；原卡上已有服务继续运行，吞吐属于共享负载条件。

最初的 BF16 两份配置及失败报告保留。BF16 梯度对照未通过原门限，所以正式方案统一采用 **FP32**；没有放宽门限，也没有让 E1 用 FP32、E2 用 BF16。两份 FP32 配置相对于对应 BF16 配置，仅更改实验名、`training.precision` 和 `training.amp`。

FP32 两组均已通过真实 PPU 有限预检：batch=48、累积16，1 个预热更新组 + 2 个计时更新组；实际验证 batch=16，raw/EMA 保存重载检查通过。FP32 梯度探针为实际 48 张的同设备重复性检查，不是跨硬件精度验证。

| 预检验收参数 | 配置值 |
|---|---:|
| max_sample_instances（梯度探针上限） | 64 |
| validation_samples（协议配置保留值） | 8 |
| gradient_relative_l2_max | 0.1 |
| gradient_max_abs | 0.1 |
| reload_atol | 1e-6 |
| reload_rtol | 1e-5 |

`max_sample_instances=64` 是梯度探针上限，不是整个预检更新样本数上限；上述 3 个更新组累计消费 2,304 个训练样本实例。当前真实设备预检的保存重载检查使用 `eval_batch_size=16`，并非配置保留项 `validation_samples=8`。外层预检命令设置 900 秒超时、30 秒终止宽限；这不表示正式训练每 15 分钟停止。完整预检记录见 FP32 预检报告（服务器本地：`PPU_PREFLIGHT_FP32_20261026.md`）。

## 10. 结论应如何报告

- 主比较按 E1-raw、E1-EMA、E2-raw、E2-EMA 四行列出：最佳轮次、原图 AUROC/AP、固定 hflip AUROC/AP，并给出两类配对差值。
- 保持同一数据划分、预处理、阈值口径、训练预算与评价流程，不把不同协议的原模型分数直接当成可比基准。
- 当前只有 seed=42，一次运行不能证明跨随机种子的稳定收益；“max 更好”或“EMA 提分”必须由完成后的同协议指标支持。
- 预检通过仅说明有限步数的运行与检查通过，不等于长时间稳定性、最终收敛或测试集性能已经通过。
